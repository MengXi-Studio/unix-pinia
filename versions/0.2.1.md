# @meng-xi/unix-pinia v0.2.1 发布：基座运行时兼容修复 + 桥接安全的持久化登记

> v0.2.1 为**修复版本**：修复 v0.2.0 在安卓基座（动态分发运行时）上启动即抛 `UTSJSONObject cannot be cast to UTSCallback` 的问题，新增桥接安全的持久化插件登记入口 `pinia.usePersistPlugin(options)`，并允许 `StorageAdapter` 三个回调字段省略。v0.2.0 用户升级 + 改一行登记代码即可在基座上正常运行。

## 一、修复：基座运行时 ClassCastException

**现象**：v0.2.0 按文档形态在 `main.uts` 登记持久化插件后，运行到安卓基座（自定义 / 标准基座）即崩溃：

```
java.lang.ClassCastException: io.dcloud.uts.UTSJSONObject cannot be cast to io.dcloud.uts.UTSCallback
```

**根因**：基座运行时对 UTS 插件 API 的调用统一走 `UTSBridge` 动态方法表分发。`createPersistPlugin(options)` 返回的插件函数（Kotlin 闭包）跨桥回到调用方后，再作为参数传给 `pinia.use(plugin)` 时会被物化为 UTSJSONObject，而 `use` 入参的生成代码会将其强转为 UTSCallback——函数值「跨桥返回 → 再入参回传」这条边界被击穿。

**影响范围**：仅基座 / 动态分发运行时受影响（Web 纯 JS、云打包 release 纯 Kotlin 直调不走该路径）；v0.1.0 免挂载设计从未跨这条边界，不受影响。

## 二、新增：桥接安全的持久化登记

`Pinia` 实例新增链式方法 `usePersistPlugin(options)`——插件函数的构造与注册全部留在插件模块内，跨桥的只有配置对象，彻底规避上述边界：

```uts
// main.uts
import { createPinia, setActivePinia } from '@/uni_modules/ux-pinia'

setActivePinia(createPinia().usePersistPlugin({
	keyPrefix: 'ux-pinia:',
	includeStores: null,               // null = 全部 store
	excludeStores: new Array<string>(),
	serializer: null                   // null = JSON 序列化
}))
```

`createPersistPlugin` 仍保留导出（纯 Kotlin 直调场景可用）；**所有基座场景统一推荐 `pinia.usePersistPlugin(options)`**。JS 侧自定义插件不受影响，继续经 `pinia.use(myPlugin)` 注册。

## 三、StorageAdapter 三个回调字段可省略

`setStorageAdapter` 的适配器对象字段（`get` / `set` / `remove`）改为可空：省略的回调回退默认 uni storage 行为，允许只替换部分操作（如仅自定义读取）：

```uts
setStorageAdapter({ get: myGet, set: null, remove: null })
```

可空声明同时使桥接转换获得判空保护（与 `PersistOptions.serializer` 同款机制），传 null 字段不再有强转风险。

## 四、升级指南（0.2.0 → 0.2.1）

仅需两步：

1. 更新依赖：`pnpm add @meng-xi/unix-pinia@0.2.1`（或插件市场重新导入 ux-pinia）
2. `main.uts` 的持久化登记改一行：`use(createPersistPlugin({...}))` → `usePersistPlugin({...})`

store 定义与消费代码零改动——class 式写法、`$`-API、双钩子持久化契约均不变。
