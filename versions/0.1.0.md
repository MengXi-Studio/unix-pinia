# @meng-xi/unix-pinia v0.1.0 发布：uni-app x 的 Pinia 风格状态管理首个公开版本

> v0.1.0 为**首个公开版本**：标准 UTS 编写、setup 式 API，填补 uni-app x **vdom 模式 App 原生端**无法使用标准 Pinia 的空缺。Web 与 Android（Kotlin 编译链）双端全用例验证通过。

## 一、为什么做这个库

uni-app x 的 vdom 模式 App 端，标准 Pinia 因 UTS 强类型约束（Symbol、undefined、动态属性、effectScope 缺口）无法编译；官方仅推荐"导出模块级 reactive 变量"的裸方案，缺少统一范式。unix-pinia 把 Pinia 的使用习惯完整搬到 UTS：

- **setup 式 defineStore**：state 用 `Ref`、getter 用 `ComputedRef`、action 用箭头函数，与 Pinia 官方推荐写法一致
- **免挂载单例**：模块级注册表保证应用级单例，跨页面共享状态，无需 `app.use`
- **实例 API 顶层函数映射**：`patch` / `dispose` / `getStoreId` 对应 `$patch` / `$dispose` / `$id`（UTS 无 Proxy，无法在 store 对象上挂方法）
- **一比一复刻、裁掉不可实现项**：每个裁掉项（Options 式、`$subscribe`、`$onAction`、`$state`、`$patch` 对象形态等）都有明确原因与替代方案

## 二、双端实测结论

- **Web（JS 编译链）**：全用例通过，零警告
- **Android（Kotlin 编译链，真机）**：全用例通过；关键实测裁决——
  - `app.use(Pinia实例)` 原生端不触发 install → 统一免挂载模式，插件场景顶层 `setActivePinia(createPinia().use(plugin))`
  - deep watch 对 RefImpl 字段不触发 → `$subscribe` 裁掉，字段级 `watch` 替代
  - 泛型 T 进出 `Map` 必须显式 `as any`（Kotlin 泛型擦除 error17）

## 三、快速上手

```sh
pnpm add @meng-xi/unix-pinia
cp -R node_modules/@meng-xi/unix-pinia uni_modules/ux-pinia
```

```uts
export const useCounterStore = defineStore<CounterStore>('counter', (): CounterStore => {
  const count: Ref<number> = ref(0)
  const doubleCount: ComputedRef<number> = computed((): number => count.value * 2)
  const increment = (): void => { count.value++ }
  return { count, doubleCount, increment } as CounterStore
})
```
